# Competitive Scan — фаза 2

## Среда

`01-research/`. Результаты:
- `competitors/<name>.md` — по шаблону [`competitor.md`](../../../../../design/_shared/templates/competitor.md);
- `competitors/_matrix.md` — по шаблону [`competitor-matrix.md`](../../../../../design/_shared/templates/competitor-matrix.md);
- сырьё — в `sources/` со ссылками.

Предусловие: `briefs/00-research-scope.md` и `briefs/01-product-brief.md` существуют.

## Goal

Понять ландшафт альтернатив: кто закрывает какие jobs, сильные/слабые стороны,
паттерны UX, белые пятна. Не копировать конкурентов — искать возможности.

## Process

1. Из scope и brief выдели 3–7 **релевантных** альтернатив (прямые + заменители).
2. Для каждого конкурента:
   - собери факты из ссылок, скринов, отзывов;
   - сохрани сырьё в `sources/`;
   - заполни `competitors/<name>.md` — только наблюдаемое, со ссылками.
3. Объёмный сбор — **parallelization**: запусти субагентов `Task` по одному
   конкуренту, требуй сжатый отчёт ≤15 строк + путь к файлу.
4. Сведи `competitors/_matrix.md`: сегмент, main job, сильные/слабые стороны,
   белые пятна, паттерны.
5. Обнови `outputs/research-digest.md` — раздел «Выводы по конкурентам».

## Gate

Переход к `insight-synthesis` только если:
- [ ] ≥3 конкурента с заполненными файлами;
- [ ] у каждого факта есть источник;
- [ ] матрица заполнена;
- [ ] есть раздел «белые пятна».

## Rules

- Один конкурент — один файл. Не смешивать.
- Отзывы App Store / G2 / Reddit — помечать reliability: medium/low.
- Не оценивать «наш продукт» в матрице, если его ещё нет — колонка «Мы (план)»
  только из brief, помечать как гипотезу.
- Методология: Nielsen Norman competitive analysis + feature matrix.

## Output quality

Каждый слабый пункт конкурента — с цитатой или ссылкой. «Плохой UX» без
примера — недопустимо.
