# Research Scope — фаза 0

## Среда

`01-research/`. Результат: `briefs/00-research-scope.md` по шаблону
[`_shared/templates/research-scope.md`](../../../../../design/_shared/templates/research-scope.md).

Канон пайплайна: [`_shared/research/PIPELINE.md`](../../../../../design/_shared/research/PIPELINE.md).

## Goal

Превратить расплывчатую тему в исследование с границами. Без scope нельзя
переходить к брифу и конкурентам — иначе анализ размоется.

## Process

1. Прочитай вводные пользователя или `sources/00-raw-input.md`.
2. Сформулируй **исследовательский вопрос** одним предложением.
3. Определи **тип**: generative / evaluative / competitive / discovery.
4. Заполни таблицу in scope / out of scope — минимум по 3 пункта каждая.
5. Зафиксируй **критерий достаточности**: что должно быть на выходе, чтобы
   исследование считалось завершённым.
6. Сохрани `briefs/00-research-scope.md`. Обнови `NOTES.md`.

## Gate

Переход к `recursive-briefing` только если:
- [ ] исследовательский вопрос конкретен (не «изучить рынок»);
- [ ] out of scope явно исключает соседние темы;
- [ ] критерий достаточности измерим.

## Rules

- Не предлагай решения и фичи — только вопросы и границы.
- Если пользователь не знает сегмент — запиши в «открытые вопросы», не выдумывай.
- Double Diamond: эта фаза — **Discover**, не Define solution.
