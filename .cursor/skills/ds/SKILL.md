# DS — роутер группы

Среда: `02-design-system/`, строгая изоляция. Задача выполняется целиком внутри среды,
наружу уходит только `outputs/ds-manifest.md`.

Подскиллы лежат в `subskills/<имя>/SKILL.md` — прочитай нужный и работай по нему.

| Задача | Подскилл |
|--------|----------|
| разобрать визуальный стиль по референсу в `STYLE_GUIDE` | `style-decompose` |
| DS **нет**, есть бандл Claude Design — собрать её в новом файле Figma | `handoff-to-figma` |
| DS **уже есть** — разово проиндексировать в папку `ds/` | `figma-ds-link` |
| связать DS с кодовой базой надолго: токены, Code Connect, дрифт | `design-system-sync` |
| объём большой — вынести в субагент с чистым контекстом | `ds-isolated-session` |

## Выбор по направлению

Ключевой признак — направление и жизненный цикл, а не тема.

| Направление | Подскилл |
|-------------|----------|
| референс → правила | `style-decompose` |
| код или бандл → Figma | `handoff-to-figma` |
| Figma → локальный индекс | `figma-ds-link` |
| Figma ↔ код, постоянно | `design-system-sync` |

Как именно ходить в Figma — не здесь, а в `infra/figma-mcp`: OAuth, разбор ссылок,
лимиты, последовательности вызовов. Все подскиллы группы — надстройки над ним.

## Дедуп-вахта

- `figma-ds-link` и `design-system-sync` пересекаются на инвентаризации примерно на
  треть. Канон инвентаризации — `figma-ds-link`; `design-system-sync` зовёт его,
  а не повторяет.
- Реализация компонентов в коде — это среда `05-code` и группа `build`. Здесь только
  описание системы и её связь с кодом.
- `ds-to-storybook` живёт в группе `build`: он собирает библиотеку из бандла,
  а не описывает систему.
