# Infra — роутер группы

Работает в любой среде. Подскиллы лежат в `subskills/<имя>/SKILL.md` — прочитай
нужный и работай по нему.

| Задача | Подскилл |
|--------|----------|
| ссылка figma.com, OAuth, разбор ссылки, лимиты, чтение и запись | `figma-mcp` |
| проверка git, github, remote, теги, авторизация gh | `git-github-check` |
| задача упирается в артефакт или изменение другой среды | `env-handoff` |
| библиотека скиллов разрослась, дублируется, требует пересборки | `skills-architect` |

## Figma — базовый слой

`figma-mcp` загружается **до** любого другого Figma-скилла. Он отвечает на вопрос
«как ходить в Figma»: проверка сессии, OAuth при первом вызове, разбор ссылки,
маршрутизация по `02-design-system/figma/registry.md`, порядок вызовов, лимиты.

Предметные Figma-скиллы (`ds/figma-ds-link`, `ds/handoff-to-figma`,
`build/figma-to-proto`) — надстройки над ним, а не альтернативы.

## Границы сред

`env-handoff` — единственный законный способ попросить что-то у чужой среды.
Прямое редактирование чужих каталогов запрещено правилами в `.cursor/rules/`.

## Новые скиллы

Скилл не кладётся в библиотеку как есть: сначала читается целиком, определяется тип
(знание, инструмент, гибрид), строится карта пересечений по
[`_shared/skills-map.md`](../../../design/_shared/skills-map.md), и только потом он вшивается
подскиллом в существующую группу. Новая группа верхнего уровня — отдельное решение
пользователя.

Вытесненный скилл не удаляется, а уезжает в `_archive/` с пометкой, кто забрал его роль.

После любого изменения в библиотеке скиллов обнови [`infoSkills.md`](../../../infoSkills.md)
в корне — человекочитаемый справочник «что и когда».
