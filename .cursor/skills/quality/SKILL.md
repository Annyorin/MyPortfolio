# Quality — роутер группы

Среды: `04-prototype/` и `05-code/`. Подскиллы лежат в `subskills/<имя>/SKILL.md` —
прочитай нужный и работай по нему.

| Задача | Подскилл |
|--------|----------|
| соответствие дизайн-системе, a11y, полнота состояний | `design-review` |
| узнаваемые ИИ-паттерны: indigo, border-left, эмодзи-иконки | `design-anti-slop` |
| «похоже, но дёшево»: свет, типографика, краски, кромки | `design-decompose` |
| анимации, easing, микровзаимодействия | `emil-design-eng` |

## Что именно проверяем

Четыре подскилла отвечают на четыре разных вопроса. Путаница между ними — главная
причина бесполезных ревью.

| Вопрос | Подскилл |
|--------|----------|
| соответствует ли макет **нашей системе** | `design-review` |
| опознаётся ли макет как **сделанный нейронкой** | `design-anti-slop` |
| дотягивает ли макет до **визуального эталона** | `design-decompose` |
| ощущается ли интерфейс **живым** | `emil-design-eng` |

## Режимы

**Точечный.** Назван конкретный аспект — читается один подскилл.

**Полный прогон** («проверь целиком», «перед сдачей»). Запусти подскиллы параллельно
через `Task` как read-only субагентов, по одному на аспект, и сведи отчёты: убери
пересечения, отсортируй находки по эффекту и трудозатратам. Правки вносит только
основной контекст и только после подтверждения пользователем.

## Границы

Замечание, требующее изменения самой дизайн-системы, здесь не исправляется:
оно оформляется контрактом в среду 2 через `infra/env-handoff`.

`design-review` берёт систему из `04-prototype/mirror/ds-mirror.md`, а не из среды 2.

## Дедуп-вахта

- Анти-паттерны частично совпадают у `design-anti-slop` и `design-decompose`
  (капс-лейблы, нарисованные бордеры, альфы вместо красок). Канон каталога —
  `design-anti-slop/references/catalog.md`; `design-decompose` по этим темам
  неавторитетен.
- Критика результата генерации в петле — это `build/design-loop`, а не ревью здесь.
