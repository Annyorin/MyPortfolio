# PRD — Сводный дашборд программы «А» (обучение + атаки)

## 1. Резюме
Отдельная страница сводной аналитики в программе «А»: актуальный срез / последняя кампания по атакам и обучению, Risk Score, топ уязвимых с ФИО, сравнение подразделений без порога «плохо», срезы HR и SOC, экспорт под доклад и CTA назначения обучения. Цель — убрать ручную склейку Excel/Word→PDF и ускорить решения ИБ и зрителей CISO.  
→ `briefs/01-product-brief.md`, `insights/jtbd.md` (J1)

## 2. Problem statement
Специалисты ИБ и зрители CISO/CTO/Директор ИБ собирают сводку по обучению и атакам вручную (Excel / Word→PDF), потому что нет единого экрана актуальной картины. Из‑за этого доклады, назначение курсов и оценка эффективности программы дороже и менее связны.  
→ `briefs/01-product-brief.md`, `insights/pains.md` (P1–P4)

## 7. Решение (high-level)
Отдельная страница «Сводная аналитика» в «А»: один primary-вид для ИБ с актуальным срезом; экспорт для зрителей; отдельные потребности/срезы HR и SOC. Раздел «Отчёты» сохраняется. Без UI-спеки.

### In scope
- Первый экран: **последняя кампания / актуальный срез** (не тренд 3–6–12)
- **Risk Score** / единый индекс + пользователи по уровню риска
- Метрики атак: open / click / submit / report / attachment (+ macro где есть в данных)
- Метрики обучения: проходит / не закончили / завершили (и HR-срез образования)
- **Топ уязвимых с ФИО на сводке**
- Сравнение подразделений: болевые точки / типы атак **без** порога «плохо»
- Срезы/потребности: **HR = обучение**; **SOC = уязвимые + частые инциденты**
- Экспорт под доклад (PDF или аналог schedule — уточнить в delivery)
- CTA «назначить обучение» где уместно (с топа / сводки)
- Число кампаний / дата последней кампании; динамика **последней** атаки

### Out of scope
- Dual-mode «ИБ / руководство» на одной странице
- Подмена дашборда разделом «Отчёты»
- Обязательный тренд 3–6–12 на первом экране
- Полный редизайн остальных разделов продукта
- Кабинет учащегося
- Traffic-light / единый порог «плохо» по подразделениям

### Non-goals
- Стать заменой SIEM / полного SOC-workflow
- Стать корпоративным LMS для HR beyond awareness-среза
- Пиксельный UI / IA карта (следующая среда)

→ решения человека в brief; `jtbd.md` Non-jobs

## 9. Требования

### Функциональные
1. Отдельный маршрут/страница сводной аналитики (не раздел Отчёты).
2. Данные первого экрана = последняя кампания и/или org-актуальный срез (продуктово уточнить дефолт).
3. Виджеты/блоки: Risk Score; метрики атак; статусы обучения; топ ФИО; подразделения (болевые точки/типы); метаданные кампаний.
4. Экспорт актуального среза для доклада.
5. CTA назначения обучения с контекстом уязвимого (где уместно).
6. Отдельные представления или эквивалентные срезы для HR и SOC (не toggle ИБ/руководство).
7. Ограничение доступа к ФИО по ролям + возможность аудита просмотра (constraint).

### Нефункциональные
- Доступность ролевая (ИБ / HR / SOC / зритель).
- PII: ФИО на сводке — только авторизованным ролям; соответствие политике ПДн заказчика.
- Производительность: сводка должна открываться без «ручной сборки» ожиданием выгрузок (target уточнить в delivery).
- a11y и визуал — вне research (Prototype / DS).

### Интеграции
- Чтение метрик из существующих модулей Атаки и Обучение «А».
- Экспорт (файл/schedule) — стык с текущим разделом Отчёты **без** подмены.
- Внешняя SIEM для SOC — **не** must v1 (допущение A4).

→ `assumptions.md` A2–A4, A7

## 10. Метрики успеха
| Метрика | Baseline | Target | Срок |
|---------|----------|--------|------|
| Время сборки сводки для доклада (timed task) | as-is из интервью / замер | −50% vs baseline | прототип / пилот |
| Доля докладов без Excel-склейки | ~0 (интервью) | ≥70% циклов кампании | 1–2 цикла после релиза |
| Уверенность «эффект программы виден» (руководитель анализа, 1–5) | низкая (связка не видна) | ≥4 у ≥3/5 участников теста | прототип H5 |
| Запрос dual-mode в тестах | — | 0 критичных запросов при наличии экспорта | H3 |

→ brief OKR; `hypotheses.md` H2–H5

## 11. Гипотезы и риски
Топ-3 проверки: **H2, H3, H4**.  
Ключевые риски: **A2** (PII/комплаенс ФИО), **A3** (доверие к формуле Risk Score), **A4** (определение «частых инцидентов» для SOC).  
→ `insights/hypotheses.md`, `insights/assumptions.md`

## 12. Открытые вопросы
1. Точная **формула Risk Score** и источники полей (A3).  
2. Дефолт первого экрана: строго «последняя кампания» vs «org-срез поверх последней».  
3. Формат экспорта v1: one-shot PDF vs schedule (US8 vs US14).  
4. Определение **«частые инциденты»** в данных «А» без SIEM (A4).  
5. Матрица ролей доступа к ФИО (A2).  

_Не блокируют старт IA/прототипа primary-сводки; блокируют уверенный SOC-срез и юридический OK ФИО._
