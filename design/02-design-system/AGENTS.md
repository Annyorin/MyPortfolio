# Среда 2 — Design System (строгая изоляция)

Слой связи между Figma и текстовым описанием дизайн-системы. Здесь живёт снимок
дизайн-системы из Figma, её foundations и компоненты, и отсюда же Figma менеджерится:
создание новых экранов и компонентов, синхронизация изменений.

## Строгая изоляция — обязательное правило

Задача, адресованная этой среде, **выполняется целиком внутри `02-design-system/`**.

- Не читаю и не пишу файлы других сред.
- Не выношу шаги наружу и не прошу другие среды что-то сделать по ходу задачи.
- Наружу отдаю ровно один файл: `outputs/ds-manifest.md`.
- Входящие запросы принимаю только как контракты в `_shared/contracts/`
  (см. [протокол](../_shared/contracts/README.md)).

Среда объёмная, поэтому при работе с ней держи контекст узким: читай файлы точечно
по индексам ниже, а не каталоги целиком. Для длинных задач синка запускай отдельный
субагент с чистым контекстом и требуй от него сжатую сводку.

## Структура

| Каталог | Содержимое |
|---------|------------|
| `figma/` | реестр привязки к Figma: fileKey, node-id, лог синхронизаций |
| `foundations/` | цвет, типографика, сетка, отступы, радиусы, тени, motion |
| `components/` | по файлу на компонент: анатомия, варианты, состояния, правила применения |
| `patterns/` | композиции компонентов: формы, шапки, списки, пустые состояния |
| `outputs/` | `ds-manifest.md` — публичное зеркало для среды 4 |

Индексы: [`figma/registry.md`](figma/registry.md), [`components/INDEX.md`](components/INDEX.md),
[`foundations/INDEX.md`](foundations/INDEX.md).

## Работа с Figma MCP

Протокол подключения, OAuth, разбор ссылок и последовательности вызовов — в скилле
`figma-mcp` (`.cursor/skills/figma-mcp/SKILL.md`). Загружай его перед первым
обращением к Figma в сессии.

Связь «Figma ↔ текст» держится на [`figma/registry.md`](figma/registry.md): проект,
файлы, компоненты, node-id, назначение. Узел, к которому обращались на запись, обязан
иметь строку в реестре.

Каждая операция чтения или записи фиксируется строкой в `figma/sync-log.md`.

## Рабочий цикл

1. Определи тип задачи: **синк из Figma**, **изменение в Figma** или **описание системы**.
2. Синк из Figma: вытяни узел → обнови файл в `foundations/` или `components/` →
   обнови строку в `registry.md` и индекс → запиши в `sync-log.md`.
3. Изменение в Figma: найди существующий компонент → внеси изменение → отрази его
   в текстовом описании и реестре → обнови `sync-log.md`.
4. В конце любой задачи обнови `outputs/ds-manifest.md` и подними его `version`.

Синхронизация — **сразу**, без откладывания: см. [`_shared/figma-code-invariants.md`](../_shared/figma-code-invariants.md).

## Инвариант

Текстовое описание, реестр и Figma не расходятся. Расхождение фиксируется в
`figma/sync-log.md` как дрейф и устраняется до завершения задачи.
