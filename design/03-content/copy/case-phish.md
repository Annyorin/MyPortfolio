## Слой A — факты

| Поле | Черновик |
|------|----------|
| Продукт | InnoPhish учит людей не вестись на фишинг. Кейс — сводный дашборд (обучение + атаки + реакции), не весь продукт. |
| Период / платформа | 2024–2026 · Desktop. |
| Роль | UX/UI: Discovery и ux-исследование для дашборда, макеты. |
| Команда | 4 фронтендера, 4 бэкендера, дизайнер, проджект-менеджер; стейкхолдеры CISO и директор ИБ. |
| Сцена «до» | Учебный фишинг + статистика вручную в Excel/Word. Курсы по итогам атак. |
| Боль человека | Нет одного экрана «обучение + атаки». Нет ответа «насколько эффективно обучение». Нет готового файла для руководства. |
| Цена для бизнеса | Часы ИБ на статистику и обучение. Доверие заказчиков к эффекту курсов. Нет делегирования обучения в HR. |
| Критерии успеха | Меньше времени на сводку; аналитика одним файлом; курсы закрывают пробелы; делегирование в HR. |
| Результат | Страница дашборда в прод. После теста — три вкладки: Атаки / Реакции / Обучение. Среднее время сценария теста: 3,4–3,5 мин → 45 сек. |
| Доказательство | Коридор / модерируемый тест n=8. ~60% реакций — до дашборда. |
| Не стали | Dual-mode ИБ/руководство; дашборд как второй «Отчёт». |

JTBD (intro): когда нужно закрыть доклад по эффективности программы обучения, хочу за один заход увидеть обучение и атаки в актуальном срезе, чтобы не собирать Excel/Word/PDF. Сетка JTBD на сайте — **7** карточек (Figma).

Программа для повышения осведомлённости сотрудников в области информационной безопасности… + абзац про рассылки / аналитику / курсы / отчётность (Figma Fill_Block).

### Контекст + вводные блоки (`intro_title` / `intro_body`)

`intro_title` = Контекст задачи.

Тело: сцена Excel/Word → ## Цель / ## Аудитория / ## Проблема для пользователей / ## Проблема для бизнеса / ## Критерии успеха (канон Figma `509:18872`).

### Исследование (`analysis_body`, длинная)

Marker «Проанализировала конкурентов…» → ## Конкуренты → `[[img:case.phish.competitors]]` → требования / не копировать / интервью (markers) → ## Результаты интервью → ## JTBD (7) → ## Триггеры → ## Ценности пользователей → ## Гипотезы (5).

Убрано: блок «Вопросы пользователям» (заменён на «Результаты интервью»).

### Проектирование (`design_body`, длинная)

## Информационная архитектура + `[[img:case.phish.ia]]`  
## User Flow + `[[img:case.phish.flow]]`

Убрано: ## Бизнес-схема (+ `[[img:case.phish.business]]` из текста страницы; файл ассета на диске можно оставить).

### UX-тест (`ux_test_body`)

Сравнение 2 vs 3 вкладок; цель теста; сценарий с картинками `test_2tabs` / `test_3tabs`; выводы и 3,4 мин → 45 сек. Без отдельного подблока «ЦА» (как в Figma).

### Финальные макеты (`finals_body`)

Изменения + `final_1` / `final_2` + синк с разработкой + дизайн-ревью (без дубля метрики времени — она в UX-тесте / результате).

`conclusions_title` = Результат и ограничения.  
`nav_conclusions` = Результаты.
