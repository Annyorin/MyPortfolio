# Среда 4 — Prototype

Сборка экранов и флоу в Figma на зеркале дизайн-системы, с контентом из среды 3.

## Границы

- Работаю только в `04-prototype/`.
- Входы: `02-design-system/outputs/ds-manifest.md` и `03-content/outputs/content-package.md`.
  Внутренности этих сред не читаю.
- Наружу отдаю `outputs/build-log.md`.
- Дизайн-систему **не меняю**. Нужен новый или изменённый компонент — контракт к среде 2
  (см. [протокол](../_shared/contracts/README.md)), затем ожидание.

## Зеркало дизайн-системы

`mirror/` — локальная копия того, что доступно для сборки: список компонентов,
их варианты и токены, взятые из `ds-manifest.md`. Это read-only проекция.

Правило свежести: перед сборкой сверь `mirror/ds-mirror.md` с манифестом среды 2.
Разошлись — обнови зеркало, потом собирай. Собирать на устаревшем зеркале нельзя.

## Структура

| Каталог | Содержимое |
|---------|------------|
| `mirror/` | зеркало дизайн-системы, read-only |
| `screens/` | спецификации экранов + [`SCREEN-MAP.md`](screens/SCREEN-MAP.md) — связь с узлами Figma |
| `flows/` | связи между экранами, переходы, состояния |
| `outputs/` | лог сборок и ссылки на созданные узлы Figma |

Протокол работы с Figma — в `infra/subskills/figma-mcp`, загружай перед первым
обращением. Скиллы этапов — в группах `structure`, `build` и `quality`.

## Рабочий цикл

1. Обнови зеркало из `ds-manifest.md`.
2. Опиши экран в `screens/` — из компонентов зеркала и ключей контент-пакета.
   Компонента нет в зеркале — контракт к среде 2, сборка ставится на паузу.
3. Собери в Figma через MCP: `search_design_system` для поиска компонентов,
   затем `use_figma` для сборки экрана.
4. Свяжи экраны в `flows/`.
5. Запиши строку в `screens/SCREEN-MAP.md` и в `outputs/build-log.md`:
   экран, node-id, версия зеркала.

## Инвариант

Ни один элемент экрана не создаётся вручную, если в зеркале есть подходящий компонент.
Отсутствие компонента — это сигнал для среды 2, а не повод нарисовать своё.
