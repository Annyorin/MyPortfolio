Программа А — сводный дашборд — вайрфреймы

Структура страницы сводной аналитики (обучение + атаки): primary ИБ, срезы HR/SOC, empty/loading, назначение обучения и выход в существующие разделы. Паттерны: Risk Score + attack/training блоки (KnowBe4/Proofpoint), топ уязвимых с ФИО на сводке, экспорт вместо dual-mode, сравнение подразделений без traffic-light. Это структура, не визуальный стиль.

Первый экран = последняя кампания / актуальный срез Нет dual-mode ИБ/руководство Дашборд ≠ Отчёты HR = обучение · SOC = уязвимые + инциденты ФИО топа на сводке · без порога «плохо»

Логика, которую не видно на каркасах

Данные первого экрана: последняя кампания и/или org-актуальный срез — без UI тренда 3–6–12. Подразделения: сортировка/подпись по болевым точкам и типам атак; запрещены traffic-light и единый порог «плохо». PII: ФИО топа только ролям с доступом; иначе маскирование / агрегат (A2). Экспорт: one-shot актуального среза; schedule/архив — через Отчёты, не подмена дашборда. Срезы: HR не тащит Risk/атаки как primary; SOC не заменяет SIEM. Пустые вложенные блоки: нет уязвимых → текст в топе без CTA; нет обучения → нули + ссылка в Обучение. Кабинет учащегося: в навигации shell дашборда не показываем как цель.
