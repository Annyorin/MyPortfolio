3. Логика вне каркаса

  • Реакция — событие учебной атаки: переход по ссылке · открытие вложения · отправка данных (и опц. report отдельно, не в «уязвимости»).
  • Уязвимый сотрудник — есть ≥1 опасная реакция в срезе (не репорт). Формула — open Q / Risk.
  • Устойчивость (топ-5) — обратная сторона: нет опасных реакций / есть репорты / низкий risk. Не смешивать с лидерами обучения.
  • Частые / repeat clickers: колонка «Кампаний» = число разных учебных кампаний с этой реакцией. Порог ≥2 (или ≥3 по Canham/KnowBe4). Не VAP.
  • Статус обучения у людей (обязательно в списках риска / repeat / отдела): завершено · провалено · в процессе · не начато — тот же словарь, что на вкладке Обучение. Контекст «после курса» = опасная реакция при статусе «завершено» (и опц. «провалено» курса). Такой кейс выше приоритета, чем первый клик у «не начато»: обучение уже было, поведение не сменилось → remediация / другой курс, не «просто назначить базовый».
  • CTA по статусу: не начато → «Назначить»; в процессе → «Напомнить»; завершено/провалено + реакция → «Дообучить». Все → DASH-ASSIGN с разным префиллом.
  • Отделы по типу реакции — тот же пул подразделений, три фильтра; не три разных KPI «плохо».
  • Фильтр подразделений (гипотеза): в «Все» виден топ-5 критичных; конкретный отдел вне топа — через чип → поиск + дерево (multi-select / include children). Scope = уязвимые. Кадры: reactions-dept-filter-wireframe.html.
  • Не делать: traffic-light по отделам; dual-mode; подмену разделом Атаки; путать вкладку Обучение со списками людей на Реакциях; скрывать обучение у repeat clickers.
  • Open Q: вкладка Реакции vs тонкий SOC; порог «часто»; входит ли «провалено» курса в «после курса»; формула риска с весом post-training fail; дерево фильтра = только узлы с уязвимыми или полное org.
