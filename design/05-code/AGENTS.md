# Среда 5 — Code

Кодовое воплощение дизайн-системы: токены, React-компоненты, Storybook, живой прототип.
Эта среда — второе зеркало дизайн-системы, наряду с прототипом: там она отражается
в Figma, здесь — в коде.

## Границы

- Работаю только в `05-code/`.
- Входы: `02-design-system/outputs/ds-manifest.md` (истина о системе) и
  `04-prototype/outputs/build-log.md` (что уже собрано в Figma).
  Внутренности этих сред не читаю.
- Наружу отдаю `outputs/code-manifest.md`.
- Дизайн-систему **не меняю**. Расхождение кода с системой — это либо ошибка кода,
  либо контракт к среде 2 через `infra/subskills/env-handoff`.

## Направление истины

Figma — источник, код — следствие. Значение, которого нет в манифесте среды 2,
не появляется в токенах: оно либо берётся из манифеста, либо запрашивается контрактом.
Обратное направление (код → Figma) возможно только как явная задача среды 2.

## Структура

| Каталог | Содержимое |
|---------|------------|
| `tokens/` | токены в формате проекта: CSS Custom Properties, TS, конфиг |
| `components/` | компоненты в стеке проекта, по одному на файл |
| `stories/` | истории Storybook: варианты, размеры, состояния, playground |
| `outputs/` | `code-manifest.md` — что реализовано и на какой версии системы |

## Рабочий цикл

1. Сверь версию `outputs/code-manifest.md` с `version` манифеста среды 2.
2. Разошлись — сначала обнови токены, потом компоненты, потом истории.
3. Реализуй только то, что есть в манифесте. Приоритет: атомы → молекулы →
   организмы → шаблоны.
4. Значения бери из токенов, а не из макета. Хардкод цвета или отступа в компоненте —
   ошибка, даже если визуально совпало.
5. Имена компонентов и вариантов — **один в один** с Figma и `ds-manifest.md`
   (см. [`_shared/figma-code-invariants.md`](../_shared/figma-code-invariants.md), п. 2).
6. После значимой итерации — сверка паритета Figma ↔ код (скилл `design-system-sync`,
   фаза дрифта; см. инварианты, п. 4).
7. Обнови `outputs/code-manifest.md`.

## Инвариант

Каждый компонент кода трассируется до строки в манифесте среды 2. Компонент без
такой трассировки либо лишний, либо система не описана — и это выясняется, а не
оставляется на потом.
