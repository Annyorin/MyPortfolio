# Метасреда продуктового дизайна

В этом репозитории метасреда вложена в `design/` и вызывается субагентом `designer`.
Скиллы — в корневом `.cursor/skills/`. Точка входа — [`AGENTS.md`](AGENTS.md).

```
AGENTS.md                 корневой оркестратор: маршрутизация и границы
infoSkills.md             справочник скиллов: что делают и когда вызываются
_shared/
  registry.md             таблица триггеров, публичных выходов и скиллов по средам
  figma-code-invariants.md  обязательные правила Figma ↔ код (6 пунктов)
  contracts/              протокол передачи задач между средами
  templates/              шаблоны артефактов
  reference/              справка для человека, агентами не читается
01-research/              брифы, конкуренты, инсайты      → research-digest.md
02-design-system/         Figma-синк, foundations, компоненты → ds-manifest.md  (изолирована)
03-content/               стратегия, тексты, изображения  → content-package.md
04-prototype/             зеркало DS в Figma, экраны      → build-log.md
05-code/                  зеркало DS в коде, Storybook    → code-manifest.md
.cursor/
  rules/                  правила границ, подключаются по путям
  skills/                 6 групп-мультискиллов, грузятся по вызову
```

Раскладка по слоям: правила — границы сред (подключаются по путям), скиллы —
процедуры (по вызову), каталоги сред — артефакты, `_shared/reference/` — справка
для человека. Процедура не кладётся в каталог среды, чтобы не попадать в контекст
каждой задачи этой среды.

Скиллы собраны в 6 групп по этапам работы: `discovery`, `structure`, `ds`, `build`,
`quality`, `infra`. Триггерятся только роутеры групп, подскилл роутер читает как файл.
Что где лежит — в [`_shared/skills-map.md`](_shared/skills-map.md).
Обзор и карта веток «с чего начать» — в [`infoSkills.md`](infoSkills.md).

## Figma

Подключение — официальный remote MCP-сервер Figma по OAuth, чтение и запись.
Протокол в скилле `figma-mcp`. Связь с Figma держат два реестра:
`02-design-system/figma/registry.md` (проект, файлы, компоненты, node-id) и
`04-prototype/screens/SCREEN-MAP.md` (экраны прототипа ↔ узлы Figma).

## Как это работает

Каждая среда — самодостаточный контекст со своим `AGENTS.md`, своим `NOTES.md` и одним
публичным файлом в `outputs/`. Снаружи среда видна только через этот файл, поэтому
задача не растекается по всему пространству.

`02-design-system/` изолирована строго: адресованная ей задача выполняется целиком
внутри неё, объёмные операции выносятся в субагент с чистым контекстом. Остальные
среды изолированы мягко — межсредное взаимодействие возможно, но только через
контракт в `_shared/contracts/`.

## С чего начать

1. Заполнить `02-design-system/figma/registry.md` — fileKey библиотеки и продуктового файла.
2. Положить бриф в `01-research/briefs/`.
3. Дальше формулировать задачи по одной среде за раз.
