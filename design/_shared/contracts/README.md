# Протокол передачи между средами (handoff)

Среды не вызывают друг друга напрямую. Они обмениваются **контрактами** — короткими
файлами в `_shared/contracts/`, которые фиксируют запрос и его результат.

## Когда нужен контракт

- Среде нужен артефакт, которого нет в чужом `outputs/`.
- Среде нужно изменение внутри другой среды (например, Prototype хочет новый компонент
  в Design System).

Если нужный артефакт уже лежит в чужом `outputs/` — контракт не нужен, просто прочитай его.

## Формат

Файл `_shared/contracts/<NNN>-<from>-to-<to>.md`:

```markdown
---
type: contract
from: 04-prototype
to: 02-design-system
status: open        # open | accepted | done | rejected
opened: YYYY-MM-DD
---

## Запрос
Одно предложение: что именно нужно.

## Зачем
Контекст, достаточный для принятия решения без чтения среды-заказчика.

## Критерий приёмки
Проверяемое условие завершения.

## Результат
Заполняет среда-исполнитель: ссылка на артефакт в её `outputs/` + краткая сводка.
```

## Правила исполнения

1. Заказчик создаёт контракт и **останавливается**. Он не идёт делать работу сам.
2. Исполнитель выполняет работу целиком внутри своей среды, публикует результат в свой
   `outputs/`, заполняет раздел «Результат» и ставит `status: done`.
3. Заказчик продолжает, читая только `outputs/` исполнителя.
4. Контракт со `status: done` не редактируется — на изменения заводится новый.
