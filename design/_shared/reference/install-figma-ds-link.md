# Скилл figma-ds-link

Скилл с эфира «Собираем макеты по дизайн-системе». Привязывает агента к твоей дизайн-системе в Figma: один раз строит индекс компонентов, токенов и правил сборки, и дальше агент работает по индексу, а не сканирует весь файл при каждом запросе. Результат: агент попадает в компоненты, держит токены и собирает консистентные макеты.

Работает в любом агенте, который понимает формат скиллов: Claude Code, Codex и другие. Для работы нужен подключённый Figma MCP.

## Установка

Скопируй папку `figma-ds-link` (внутри один файл `SKILL.md`) в папку скиллов агента:

- **Claude Code**: в папку проекта `.claude/skills/figma-ds-link/SKILL.md` (или глобально в `~/.claude/skills/`).
- **Codex и совместимые**: `~/.agents/skills/figma-ds-link/SKILL.md` либо в папку проекта `.agents/skills/`.

Перезапусти агента и проверь: «покажи, какие скиллы ты видишь».

## Как пользоваться

Первый запуск (настройка, один раз):

- «Подключи мою дизайн-систему: вот ссылка на Figma-файл. Проиндексируй её по скиллу figma-ds-link»

Агент построит в проекте папку `ds/`: каталог компонентов с назначениями, карту токенов и плейбук с правилами сборки. Дальше обычная работа:

- «Собери экран настроек по нашей дизайн-системе»
- «Сверь индекс с файлом: что поменялось»

## Что важно знать

- Индексация большого файла идёт порциями, первый прогон может занять время. Дальше всё быстро: агент ходит по индексу.
- ID узлов Figma нестабильны, поэтому скилл принципиально хранит имена, а карту узлов строит в начале сессии. Это не баг, это защита от битых ссылок.
- Макеты собирайте в отдельном файле с подключённой библиотекой, не внутри файла самой ДС: правило из плейбука, выстраданное практикой.
