# Как подавать данные агенту для исследования

Форматы входа, которые дают точный анализ. Чем структурированнее вход —
тем меньше галлюцинаций и тем проще трассировка до PRD.

## Принцип

Агент различает три слоя данных:

| Слой | Куда класть | Что это |
|------|-------------|---------|
| Сырьё | `sources/` | цитаты, скрины, ссылки, заметки с интервью — без интерпретации |
| Наблюдения | `competitors/`, части `briefs/` | структурированные факты по шаблону |
| Синтез | `insights/` | выводы со ссылками на слои выше |

Не смешивай слои в одном файле.

## Минимальный старт (если опыта мало)

Достаточно трёх вещей в свободной форме — агент разложит по шаблонам:

```markdown
## Тема
[одно предложение: что хотите исследовать]

## Зачем
[какое решение примете по итогам]

## Что уже знаете
- [факт или ссылка]
- [ещё факт]

## Чего не знаете
- [вопрос 1]
- [вопрос 2]

## Конкуренты / альтернативы
- [название или ссылка]
```

Сохрани как `sources/00-raw-input.md` или просто вставь в чат — агент создаст
`briefs/00-research-scope.md` и запустит фазу 1.

## Форматы по типу данных

### Ссылки и статьи

Файл `sources/<slug>.md`:

```markdown
---
type: source
url: https://...
accessed: 2026-09-02
reliability: high | medium | low
---

# <заголовок>

## Цитата / выдержка
> дословный фрагмент

## Заметка
что из этого важно для нашего исследования
```

### Конкурент

Один файл `competitors/<name>.md` по шаблону
[`../templates/competitor.md`](../templates/competitor.md).
Плюс скриншоты — в `sources/screenshots/<name>/` с подписью в markdown.

### Интервью / опрос

` sources/interviews/<id>.md`:

```markdown
---
type: interview
participant: P03
role: [роль]
date: 2026-09-02
---

## Контекст
как попал в ситуацию

## Цитаты (дословно)
> «…»

## Jobs / боли (пометка интервьюера, не цитата)
- …
```

### Скриншоты и скринкасты

- Файлы: `sources/screenshots/<контекст>/01.png`
- Рядом: `sources/screenshots/<контекст>/README.md` — что на скрине, откуда, дата.
- В чат можно прикрепить изображение + подпись «конкурент X, экран оплаты».

### Таблицы и CSV

Числовые данные — `sources/data/<name>.csv` + однострочное описание колонок
в `sources/data/<name>.md`. Агент не выдумывает цифры: если CSV нет — пишет
гипотезу.

## Чего избегать

| Плохо | Почему | Лучше |
|-------|--------|-------|
| «Сделай исследование рынка EdTech» | нет границ | scope: сегмент, география, B2B/B2C |
| Смешать выводы и факты в одном абзаце | нет трассировки | факт в `sources/`, вывод в `insights/` |
| 20 конкурентов списком | размытый анализ | 3–7 релевантных + матрица |
| Персоны с выдуманной демографией | AI-slop | JTBD: ситуация + мотивация + исход |
| Просить PRD сразу | пропущены этапы | пройти фазы 0–4 или явно сказать «сокращённый трек» |

## Команды для запуска

| Цель | Что написать агенту |
|------|---------------------|
| начать с нуля | «Запусти research-scope, тема: …» |
| только бриф | «recursive-briefing по вводным …» |
| разобрать конкурентов | «competitive-scan: [ссылки]» |
| синтез из собранного | «insight-synthesis по файлам в 01-research» |
| гипотезы | «hypothesis-builder» |
| финальный PRD | «research-to-prd» |
| весь цикл | «Полный пайплайн исследования → PRD, тема: …» |

## Сокращённый трек (если времени мало)

Допустим только при явном запросе. Пропускаются фазы 2 или 4, но в PRD
обязателен раздел «Что не исследовали» с рисками.
